## 3.3 工程结构

```
demo/
├── backend/                          # Spring Boot 单模块
│   ├── pom.xml
│   └── src/main/
│       ├── java/com/campus/market/   # 包结构见设计文档 2.3.1
│       └── resources/
│           ├── application.yml       # 公共配置（含占位环境变量）
│           ├── application-dev.yml   # 开发：sql init 每次执行、日志 DEBUG
│           ├── application-prod.yml  # 生产：日志 INFO、init 仅建表
│           ├── schema.sql            # V1 建表（幂等 IF NOT EXISTS）
│           └── data.sql              # 种子数据（分类/管理员/敏感词）
│   └── src/test/java/...             # 单测与 MockMvc 用例
├── frontend/
│   ├── package.json
│   ├── vite.config.js                # dev 代理 /api → 8080
│   └── src/
│       ├── api/                      # axios 封装 + 各模块 API
│       ├── router/                   # 路由 + 全局守卫（未登录跳转）
│       ├── stores/                   # Pinia：user、cart(无)、messageBadge
│       ├── views/                    # 页面（对应需求 1.9.1 路径）
│       ├── components/               # GoodsCard、StatusTag、OrderCountdown 等
│       └── utils/                    # 请求拦截、错误码→文案映射
├── deploy/
│   ├── market.service                # systemd 单元
│   ├── backup.sh                     # 每日备份（cron 02:00）
│   └── restore.md                    # 恢复演练步骤
├── doc/                              # 本文档包
└── README.md
```

**分层规范**：见设计文档 2.2.2；补充——DTO 不做跨层透传（Controller 收发 DTO，Service 出入领域对象/VO）；统一响应 `Result<T>`，异常一律抛 `BizException(ErrorCode)` 由 `GlobalExceptionHandler` 兜底。

| 项 | 规范 |
|---|---|
| 命名 | 类 PascalCase；方法/变量 camelCase；常量 UPPER_SNAKE；数据库表小写下划线 |

## 3.6 接口实现说明

### 3.6.1 接口 → Service → 表 映射（核心）

| 接口（设计 2.5.2） | Service 方法 | 主表 | 事务/锁要点 |
|---|---|---|---|
| API-17 下单 | OrderService.createOrder | orders + goods | tryLockGoods 条件更新 → INSERT（2.6.1） |
| API-18 支付 | OrderService.pay | orders | 状态条件 UPDATE + 凭证生成（BR-04） |
| API-19 取消 | OrderService.cancel | orders + goods | UPDATE + unlockGoods 同事务 |
| API-20 完成 | OrderService.complete | orders + goods | UPDATE 双表同事务 |
| API-30 审核 | AdminService.auditGoods | goods + audit_log | 条件更新 + AOP 审计 |
| API-34 封禁 | AdminService.banUser | user + goods + audit_log | 批量下架同事务 |
| API-25 评价 | ReviewService.review | review | UNIQUE(order_id,reviewer_id) 兜底重复评价 |

### 3.6.2 鉴权实现

1. `JwtAuthFilter` 解析 Bearer token → SecurityContext（userId+role）。
2. `SecurityConfig`：`/api/v1/auth/**`、GET 类浏览接口 permitAll；`/api/v1/admin/**` 要求 ROLE_ADMIN；其余 authenticated。
3. 属主校验在 Service：订单仅买卖双方、商品仅卖家可改（双防线，NFR-SEC-02）。
4. 登出：前端删 token；服务端提供内存黑名单（可选，默认关 [假设]）。

### 3.6.3 错误处理

- `GlobalExceptionHandler`：MethodArgumentNotValidException→A0400（字段明细）；BizException→对应码；其余→C0500+traceId。
- 前端 `utils/errorCode.js` 维护错误码→中文文案映射（与设计 2.5.3 一致）。

## 3.10 构建与部署

### 3.10.1 构建

```
# 后端
cd backend && mvn -DskipTests package   # 产出 target/market.jar
# 前端
cd frontend && npm ci && npm run build  # 产出 dist/
cp -r frontend/dist/* backend/src/main/resources/static/  # 或构建后由 Maven 前端插件自动拷贝
mvn -DskipTests package                  # 重打包为全量 jar
```

### 3.10.2 部署流程（单机）

1. 准备目录 `/opt/market/{jar,data,logs}`，设置环境变量（JWT_SECRET 等）。
2. 安装 `deploy/market.service` → `systemctl daemon-reload && systemctl enable --now market`。
3. 安装备份 cron：`crontab: 0 2 * * * /opt/market/backup.sh`。
4. 验证：`curl http://localhost:8080/actuator/health` 返回 UP。

### 3.10.3 回滚流程

| 场景 | 步骤 |
|---|---|
| 新版本异常 | `cp market.jar market.jar.bak` 先行保存 → 停服务 → 换回旧 jar → 启动 |
| 数据损坏 | 按 `deploy/restore.md`：停服务 → 覆盖最近备份 db → 启动 → TC-15 抽查 |
| 配置错误 | 环境变量核对清单（3.2.2）逐项检查后重启 |

### 3.10.4 环境差异

| 环境 | 数据库 | 日志级别 | SQL init | 数据 |
|---|---|---|---|---|
| dev（开发机） | ./data/market-dev.db | DEBUG | always | 可随时删除重建 |
| prod（服务器） | /opt/market/data/market.db | INFO | embedded | 每日备份保护 |
