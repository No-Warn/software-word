## 6.1 变更管理流程

1. 提出变更：说明动因（新需求/评审意见/缺陷/假设被推翻）。
2. 影响分析：按 6.3 模板列出受影响的 FR/NFR/BR、设计章节、开发任务、测试用例、文档章节。
3. 评审确认：产品与开发双确认后方可修改。
4. 执行修订：修改对应文档，版本号递增（V1.x），在 6.2 登记一行。
5. 同步追溯矩阵：更新"状态"列与用例映射，保证无孤儿需求。

## 6.3 影响分析模板

```
变更编号：CH-xxx
变更描述：
动因：
受影响需求：FR-xxx-xx / NFR-xxx-xx / BR-xx（列出全部）
受影响设计章节：2.x（列出全部）
受影响开发任务：T-xx（含新增/删除任务）
受影响测试用例：TC-xx（含新增/删除用例）
受影响文档章节：
验收口径变化：
回归范围：
批准人 / 日期：
```

> 规则：任何假设（05 文档 A-xx）被推翻，视为一次变更，必须走本流程；严禁只改正文不登记。
